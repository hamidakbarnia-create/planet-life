## 1. Provider execution flow

```text
Ask orchestration
→ executeAskProviderCall (budget gate → timeout AbortSignal → Conversation client)
→ classify transport / abort / usability
→ normalized AskProviderCallResult
→ on success: continue Grounding → Validation → optional Safe Regeneration
→ on initial failure: structured fallback (no grounding/validation/regen)
→ language-retry failure: retain original usable result
→ Safe Regeneration failure: retain original (P2.2-02)
→ meta.providerExecution attached (additive)
```

---

## 2. Provider-call budget enforcement

```text
ASK_MAX_PROVIDER_CALLS = 2
```

| Slot | Consumer |
| ---- | -------- |
| Call 1 | Initial provider call |
| Call 2 | **Either** language retry **or** Safe Regeneration — never both |
| Call 3+ | Impossible (`budget_exhausted`; provider not invoked) |

Explicit policy:

- If language retry uses call 2 → Safe Regeneration cannot execute (`provider_budget_exhausted` / not attempted).
- If Safe Regeneration uses call 2 → language retry cannot execute (regen path never language-retries).
- Provider failure / timeout / invalid output **must not** create a generic extra retry.
- Fallback **must not** invoke the provider.

## 3. Timeout behaviour

| Item | Value |
| ---- | ----- |
| Default | `ASK_PROVIDER_TIMEOUT_MS_DEFAULT = 25_000` |
| Config | `NEXT_PUBLIC_ASK_PROVIDER_TIMEOUT_MS` (positive finite ms; invalid → default) |
| Scope | Applied at `executeAskProviderCall` via combined AbortSignal |

Timeout classification is distinct (`failureReason=timeout`). No automatic second call.

---

## 4. Cancellation behaviour

**Mode: client abort of the local await / fetch wait — not proven hard server cancellation.**

- Boundary creates an `AbortController` timer and forwards `signal` to `fetch`.
- When the timer fires, the client stops waiting and classifies `timeout`.
- External `AbortSignal` abort classifies as `cancelled` (unless the timeout flag fired first).
- Upstream OpenAI/Railway cancellation is **not** claimed as proven hard cancellation.

---

## 5. Error classification

| Category | Meaning |
| -------- | ------- |
| `success` | Usable non-empty message; structured JSON parseable when required |
| `timeout` | Boundary timeout aborted wait |
| `network_error` | Network / TypeError transport failure |
| `http_error` | Non-OK HTTP / contract HTTP failure (`httpStatus` retained operationally) |
| `provider_exception` | Normalized SDK/provider throw (when distinguishable) |
| `empty_response` | Missing / empty / whitespace-only message |
| `invalid_output` | Non-parseable structured content when structured Ask required |
| `cancelled` | External abort |
| `budget_exhausted` | Call denied; provider not invoked |
| `unknown_failure` | Unexpected thrown value |

Raw provider exceptions, prompts, response bodies, and stack traces are not exposed on the Ask result.

---

## 6. Fallback behaviour

### Initial provider failure

- Do not run Grounding / Claim Validation on invalid provider output.
- Do not run Safe Regeneration.
- Do not consume another provider call as a generic retry.
- Return existing `buildStructuredFallback` path with `meta.fallback=true`.
- Attach unavailable grounding/validation + not-requested Safe Regeneration meta.

### Language retry failure

- Retain the valid original result.
- Do not crash; do not call provider again.
- Call budget exhausted → Safe Regeneration cannot run.

### Safe Regeneration failure

- Preserve P2.2-02: retain original; no third call; no provider switch.

## 7. Metadata changes (additive)

`meta.providerExecution`:

| Field | Meaning |
| ----- | ------- |
| `status` | `success` \| `failed` |
| `failureReason` | Last failure category or null |
| `callCount` | Attempts that consumed budget |
| `maxCalls` | Always `ASK_MAX_PROVIDER_CALLS` (2) |
| `latencyMs` | Sum of attempt latencies |
| `fallbackUsed` | Whether structured fallback / provider failure path used |
| `attempts[]` | Bounded list: `purpose`, `status`, `latencyMs`, `failureReason` |

Purposes: `initial` \| `language_retry` \| `safe_regeneration`.
