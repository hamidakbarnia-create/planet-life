## 1. Language-retry vs regeneration budget (resolved)

Existing FA/AR/RU language retry can consume a second provider call. Preferred target remains **maximum 2 provider calls** per Ask request.

**Policy implemented:**

| Slot | Consumer |
| ---- | -------- |
| Call 1 | Initial provider call |
| Call 2 | **Either** language retry **or** safe regeneration — never both |
| Call 3+ | Impossible (`ASK_MAX_PROVIDER_CALLS = 2`) |

Additional rules:

- Regenerated responses never receive a language retry.
- Regenerated validation that would itself recommend regeneration never triggers another provider call.
- If `shouldRegenerate=true` but budget is exhausted → `outcome=original_retained`, `reason=provider_budget_exhausted`.

This preserves locked language-retry behaviour without creating an uncontrolled retry chain.

---

## 2. Execution flow

```text
Provider (budgeted)
→ Parse
→ optional language retry (budgeted, FA/AR/RU only)
→ Grounding + Claim Validation (semantic candidate)
→ Safe Regeneration Decision (unchanged authority)
→ optional one-shot regeneration (budgeted, same provider)
→ Grounding + Validation of regenerated candidate
→ Deterministic comparison / selection
→ Writing Quality + Localization (selected only)
→ Final Grounding + Validation meta (observation stage)
```

## 4. Regeneration trigger behaviour

Unchanged decision thresholds (`shouldRegenerate`):

- unsupported ≥ 3
- BROKEN_REFERENCE ≥ 2
- STRUCTURAL_MISMATCH ≥ 1

Execution runs only when `shouldRegenerate === true` **and** budget remains.

---

## 5. Candidate comparison rules

Ordered failure tuple (lower is better):

1. `structuralMismatchCount`
2. `brokenReferenceCount`
3. `unsupportedCount`
4. total non-supported (`unsupported + partial + unknown`)

Regenerated wins **only** on strict improvement. Tie → original. Unavailable/invalid compare → keep original (`comparison_unavailable`).

---

## 6. Fallback behaviour

Any of the following keeps the original semantic result:

- provider error / timeout / empty / invalid parse
- grounding or validation exception / unavailable
- comparison unavailable
- no strict improvement
- provider budget exhausted
- any execution exception

The request does not crash solely because regeneration failed.

## 7. Metadata shape

Extends `meta.safeRegeneration` (backward-compatible optional fields):

| Field | Values / meaning |
| ----- | ---------------- |
| `shouldRegenerate` | Decision authority (unchanged) |
| `attempted` | Whether a regen provider call was made |
| `selected` | `original` \| `regenerated` \| `not_applicable` |
| `outcome` | `not_requested` \| `regenerated_selected` \| `original_retained` \| `regeneration_failed` \| `comparison_unavailable` |
| `reason` | Short machine reason (no prompts / user prose) |
| `originalValidationSummary` | Compact counts |
| `regeneratedValidationSummary` | Compact counts or null |

## 13. Known limitations

1. Live organic `shouldRegenerate=true` from production-like grounding remains uncommon; forced-decision staging covers execution paths.
2. When language retry consumes call 2, recommended regeneration is deferred (`provider_budget_exhausted`) — intentional budget policy.
3. Final `meta.validation` is post-WQ observation; comparison uses pre-presentation semantic validation snapshots stored on `safeRegeneration.*ValidationSummary`.
4. Full-repo `eslint` OOM’d in this WSL environment; targeted lint on changed files passed.
